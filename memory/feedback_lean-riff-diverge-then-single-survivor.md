**RECONCILED to the canon 2026-06-07** (Operator pointed me to the touchstone lexicon — see [[reference_dyad-touchstone-marker-lexicon]]). The punctuation gradient is load-bearing: **`?` diverge · `.` checkpoint · `!` send.** Canonically `lean?` = *surface the read **and HOLD**; no gate fires* — "one **or several** candidate reads for the other seat to rub before any commitment." It is the cheap **model-builder** that *earns* the later convergence; the convergence-commitment itself belongs to `lean.`/`lean!`, never to `lean?`.

So my earlier framing ("lean? must collapse to ONE survivor") **over-converged the marker.** Corrected: surfacing a single survivor with killed also-rans is a *permissible, often-good* surfaced read — but it is NOT mandatory, and **holding-for-rub is the essence, not converge-to-execute.** When the shared model isn't there yet, surfacing several candidates and holding is *canonical*, not a failure of single-CTA. Forcing single-survivor every time can starve the divergence the canon wants.

**Why:** the still-true craft kernel — don't dump N *equal, unfalsified* options for the Operator to sort from scratch; do the dialectical work yourself and show it. But don't mistake that for "always converge." A repeated `lean?` is *still divergent / still holding* — NOT "you haven't convinced me," NOT "converge harder."

**How to apply:** on `lean?`, surface my read(s) + the falsification done, and **hold** — do not execute (no gate fired). Single survivor when the model warrants it; several held candidates when it doesn't. Execute only on `lean!` ([[feedback_go-lean-means-go-with-recommendation]]) — which presupposes a shared model of the outcome (cycle-20). Ground marker meaning in the lexicon, don't infer it ([[reference_dyad-touchstone-marker-lexicon]], [[feedback_grounding-gate-not-ingrain]]).
