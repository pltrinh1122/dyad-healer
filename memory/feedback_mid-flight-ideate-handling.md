When the Operator sends a new [IDEATE] or [FEEDBACK] while I'm mid-task
(e.g., mid-edit, mid-substitution-pass, mid-commit-rhythm), the
grain-aligned pattern is:

1. **Acknowledge** the new message immediately (don't appear to ignore it).
2. **Close to a coherent atomic state** — finish the in-flight unit (the
   current Edit, the current file, the current sub-task), but DO NOT
   continue beyond it. *Coherent* = the kb/ledger/backlog doesn't end up
   half-converted, malformed, or split between two conventions.
3. **Commit the partial work** before engaging the new message — closes
   the divergence-gap (see [[dyadic-coherence-under-divergence]] —
   uncommitted work is vulnerable; the discipline is commit-before-sync
   at sub-step granularity, not just session boundaries).
4. **Then engage** the new message fully — falsification, dialectic,
   verdict — without the in-flight work hanging over the analysis.
5. **Then resume** the original task, possibly informed by the new
   dialectic's outcome (e.g., the [IDEATE] may change the wording, scope,
   or sequencing of remaining work).

**Why:** under long context, dropping in-progress work to chase the new
message risks (a) leaving the durable record in an incoherent partial
state, (b) the in-progress work falling out of focus and being forgotten,
(c) the new question getting a hurried answer because the old work is
still on the mental stack. Acknowledge + close-gap + engage cleanly is
better than either ignore-and-finish OR drop-everything.

**How to apply:**
- The "current task" granularity is one *coherent unit* (the file being
  edited, the substitution pattern within a file, the immediate Edit) —
  not the entire multi-step plan.
- If the new message is FALSIFY/IDEATE, the surfacing-and-dialectic is
  itself work that benefits from the prior work being closed.
- If the new message is an emergency-halt or correction, escalate
  emergency-stop reflex per the cross-cutting discipline.
