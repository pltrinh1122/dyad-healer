When choosing vocabulary for documents, prefer **pedestrian (everyday) terms
that are sufficiently precise** over academic / technical jargon.

**Anti-pattern:**
- "Manifold" when "shared mental model" works.
- "Substrate-experience" when "what both halves feel" or "felt sense" works.
- "Ontology" when "kinds of things" works (in some contexts).
- "Falsifiability" when "what would prove it wrong" works (in some contexts).

**Right pattern:**
- Replace jargon where pedestrian alternatives convey the same meaning with
  comparable precision.
- Keep technical terms when they ARE load-bearing (precision gain is real,
  reading-friction is acceptable, the audience handles the term).
- Form-canonical terms (tenet, wu-wei, falsification, stock/grain/fit) are
  load-bearing and stay.

**Why:** wu-wei applies to vocabulary, not just structure. Academic terms
impose force on the reader (they have to translate; they may not have read
the philosophical/mathematical lineage); pedestrian terms work with the
reader's existing grain. The form's README uses no academic jargon ("1+1=3";
"build on each other"; "the dyad makes something neither makes alone");
documents inheriting from it should reflect that grain.

**Test:** can a reasonably-educated non-specialist understand the term in
context? If yes, it's pedestrian-enough. If no, consider whether the
precision gain is worth the friction.

**How to apply:**
- Pass 5c of the drafting protocol explicitly includes a vocabulary check:
  *"technical jargon replaced with sufficiently-precise pedestrian alternatives
  where wu-wei favors."*
- When you reach for a fancy word, pause: *"is there a pedestrian alternative
  that conveys the same meaning?"* If yes, use it.
- When a reviewer asks *"could this be more pedestrian?"*, falsify the
  academic term: what does it gain that the pedestrian alternative loses?
  If the gain is small, swap.
