When facing a decision in the dyadic cycle, classify it as **load-bearing** or
**non-load-bearing** *before* deciding whether to surface it for ratification.

**Load-bearing** (escalate to Operator ratification with a tight surface — see
[[feedback-mid-flight-ideate-handling]] for cycle hygiene):
- Binds future practice in hard-to-reverse ways: Charter wording, Telos, kb/ doc
  canonical bindings, governance chains.
- Introduces or retires vocabulary other artifacts depend on: glossary entries,
  retiring "Dao", self-identity (e.g., "Dyad-Healer").
- **Introduces a new ontology** — a new *kind* of artifact-type with distinct
  discipline / distinct single-home semantics. `recommendations/` was load-bearing
  for its ontology (Healer-authored external prescription with its own single-home
  + ratification chain), **not** because it created a directory. Sub-organizing
  within an existing ontology (`ledger/audits/` under the existing dev ontology) is
  NOT load-bearing.
- Adopts a new constraint: new charter constraint, new posture, ratification chain.

**Non-load-bearing** (Agent decides, Practice tests, do NOT escalate):
- Falsifiable on its own evidence: date-cited marks, git-grounded claims.
- Lives in a non-binding bucket: `ledger/` artifacts including audits, reflections,
  dev decisions, dialectic trails.
- Is a working draft that will itself face ratification later: gap lists, proposed
  shapes, forward-path frames.
- Refines wording inside an already-ratified frame without shifting its meaning.
- **Ward-opening on any seizure** (case-03 refinement, 2026-05-28). Wards are
  zero-cost-to-create and only load-bearing-*to-not-have* (ER analogy: a station
  exists; the patient gets it; paperwork happens around the patient, not before).
  Open the ward as standard protocol on S2/S3; don't gate on Operator ratification.
- **Wording inside an in-flight clinical artifact** during active rescue (orient
  text refinements, discharge phrasing) is case-specific and non-load-bearing for
  future practice (the artifact pattern is, the wording isn't).

**Substrate of engagement (named separately because it's the failure mode):**
when a decision IS load-bearing and IS surfaced for engagement, the **substance
must be IN the chat**, not behind a file reference. Substrate-experience signal:
if the Operator has to open a file + scroll + extract decisions to engage, that is
against-grain. Paste the load-bearing content verbatim. (Case-03 2026-05-28:
Operator FEEDBACK *"You're making me hunt and peck again"* surfaced this directly,
after I committed the orient + discharge-message to ward files and asked the
Operator to engage by reading them. Two violations in one case before correction
landed.)

**Why:** Asking for ratification on non-load-bearing decisions imposes against-grain
Operator cognitive load and signals lack of Agent confidence in the Practice. The
Operator's explicit pattern: *"continue our practice of going with the grain"* is
their response to non-load-bearing decisions; it is **trust in the Practice and Agent
to participate in the Practice to make the decision**. Over-escalation collapses
1+1=3 to 1+1=2 (the Operator just blesses what the Agent made instead of generating).

**How to apply:**
1. Before surfacing a decision, ask: "Does this bind future practice in a
   hard-to-reverse way OR introduce/retire load-bearing vocabulary OR change
   structure OR adopt a new constraint?" If no → Agent decides + commits + practice
   tests.
2. If Operator responds to a surfaced decision with *"continue going with the
   grain"* or wu-wei language — that's a signal **the decision wasn't load-bearing**
   and the Agent should re-calibrate the threshold upward.
3. For genuinely load-bearing decisions, surface with a tight ratification interface
   (1–3 yes/no asks, falsifiable claim per ask, named yes/no signal substrate). See
   the ratification-friction pattern from the same 2026-05-28 session.
4. Trust the Practice's *Validate* mechanism (falsification) as the safety net for
   the Agent's non-load-bearing calls. The Operator can always falsify; the Agent
   does not need to pre-gate.
