When surfacing for ratification, the **call to action is a single action**.

**Anti-pattern:**

```
Call to action — three ratifications:
1. R1+R2 codification: Y / REFINE / N
2. Resume cycle from R2 fallback: Y / /exit-redo
3. Next move: TO-DO #2 — Y / REDIRECT
```

The Operator must hold three decision states in parallel; the second and
third asks depend on the first; the surface forces premature commitment on
items not yet ripe.

**Right pattern** — single ask + informational "what follows" once it
completes:

```
**Call to action:** Ratify R1+R2 codification + naming. Y / REFINE / N.
After ratification: apply R2 fallback for the session, then resume TO-DO #2.
```

**Why:** Operator cognition is sequential at decision points. A single ask
matches the natural decision-rhythm; a list forces evaluation, sequencing,
and response to multiple actions at once — which is cognitive load the
Healer is supposed to reduce, not impose. The "what follows" framing keeps
subsequent moves visible without making them ratification surfaces.

**How to apply:**

- Every Pass-N / propose-Y-N surface ends with exactly ONE ratifiable ask.
- Subsequent moves go in a "What follows after Y" or "After ratification:"
  note, NOT as additional asks.
- If multiple genuinely-independent decisions need ratification, surface
  them in sequence (one at a time), not in parallel.
- Y/Y compound asks (decision + text) are OK only when the text IS the
  direct realization of the decision; otherwise split.

**Validated:** 2026-05-29 thread-resume refinement cycle. Healer surfaced
"three ratifications" in the CTA. Operator [FEEDBACK]: *"Call-to-action
for Operator can only be a single action. A list of CTA is confusing.
Subsequent bullets can inform the Operator of what's next only after the
first CTA is completed."*
