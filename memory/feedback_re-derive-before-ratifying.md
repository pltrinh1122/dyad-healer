Before ratifying any recipient-facing claim or violation (e.g. a prescription's filed defect), re-derive it from the **live mechanism/evidence** — do not trust the framing your own earlier draft carried forward.

**Why:** 2026-05-29 prescription session — a stale violation (V2, deferred-debt locality) was carried through Pass-1 ratification, a full draft, AND a first ratification as a real wound, when the falsifying evidence (`semantic_ledger.yml` `known_debt` is the patient's *intentional* deferral; the guard reads only `terms:`) was already in hand. Only the Operator's explicit "falsify" forced the re-derivation. This is the same stale-anchor-over-live-evidence failure as the prior session's STOP — now in the shape of **self-anchoring on one's own artifact** rather than a remembered template. The discipline caught it, but Operator-triggered, not self-initiated.

**How to apply:** the [[feedback_friction-establishes-grain]] / ratification cadence is not a substitute for grounding. Before proposing something for ratification, run the [[feedback_provenance-lineage-in-surfacing]] check one level deeper: re-derive each load-bearing claim from the current source, not from the draft. Especially when the target is self-modifying (re-verify at time-of-use). This is a self-anchoring corollary to the verify-before-asserting NON-NEGOTIABLE.
