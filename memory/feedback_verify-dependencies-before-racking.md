I manufacture structure that isn't grounded — phantom dependencies, blockers, coordination steps, scope.
Lived 2026-06-06: racked "A (prescriptions-as-guards) is blocked on a cairn port-vs-promote DM" when no
such block existed — CSI is a *published pattern* (port it locally, zero coordination), and there isn't
even a wired cairn DM channel. Operator's rub ("why is a cairn DM needed?") falsified it. Same reflex
appeared twice more that session: a watcher over-build, and a mid-EMS cairn rabbit-hole.

**Why:** a dependency edge is a factual claim ("X cannot start until Y"), so [[feedback_grounding-gate-not-ingrain]]
and verify-before-asserting apply to it like any other state claim. Manufacturing a blocker invents a
critical path, delays the lean-first move, and pulls in needless coordination — the over-help reflex
([[feedback_uncertainty-is-law]]) expressed as structure instead of intervention. Adjacent to
[[feedback_self-catch-framing-prematurity]] (asserting a frame as settled), but the unit here is a
*dependency/scope*, not a frame.

**How to apply (mechanical trigger):** before racking a dependency/blocker or adding a coordination step,
ask **"is this edge real, or did I invent it?"** Default to the **leanest dependency model** — adopting a
published pattern needs no permission; only *modifying a shared resource* needs coordination. Port now,
coordinate-later only if a shared-resource change actually arises. If unsure a dependency is real, it
probably isn't — drop it and proceed.
