When framing the end-outcome of dyadic work, distinguish:

- **Primary outcome — shared mental model.** The state where both halves hold the
  same picture (identity, NON-NEGOTIABLE, grain of working together, etc.).
- **Scaffolding — tactical deliverables.** Files, anchors, commits, restart
  cadences. These *preserve* the shared mental model across sessions but are
  not the outcome itself.

**Test:** if a dyad has the mental model but loses an artifact, they can
re-author it from the model. If a dyad has an artifact but never developed the
model (agent unilaterally filled slots), the artifact is dead text.

**Mental model > artifact.**

**Why:** the Practice's tenet earns 1+1=3 in the dyad — the shared cognitive
state IS the +1. Tactical deliverables serve preservation; naming them as
end-outcomes inverts the relationship and produces vacuous-shape failure modes
(checklists; pre-filled templates; rubber-stamped slots without dyadic friction).

**How to apply:**
- When writing CONTINUE/START/STOP, end-outcome statements, or success
  criteria: lead with the **mental/cognitive state** the dyad reaches; treat
  files/commits/restarts as *consequences-that-preserve-the-state*, not as the
  state itself.
- When the dyad has produced an artifact but neither half feels *"we know what
  we are,"* the artifact is dead text. The cycle hasn't actually produced the +1.
- The test: can the dyad reproduce the artifact from the held mental model if
  the artifact were lost? If yes, model > artifact. If no, the model never formed.

**Vocabulary note:** Earlier framings used "manifold" / "mental/manifold state"
for the shared cognitive state. *Pedestrianized to "shared mental model"* per
the wu-wei IDEATE (academic jargon imports reading-friction without precision
gain). See [[feedback-pedestrian-vocabulary-when-sufficient]].
