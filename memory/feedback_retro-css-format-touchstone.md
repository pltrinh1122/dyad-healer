When presenting a retrospective, use **CSS = CONTINUE | START | STOP** format, following dyad-touchstone's
preferred formatting (Operator pref, 2026-06-07). **Canonical exemplar:** dyad-touchstone
`dialectic/retro/2026-06-03-session.md` (origin/main, `git@github.com:pltrinh1122/dyad-touchstone.git`) —
reference it at time-of-use rather than trusting this summary.

**The shape:**
- Title `# Retro — session <date> (<note>; CSS)` + a scope blockquote (object of the retro; two-substrate note).
- **`## 1. CONTINUE — what worked`** — two-substrate:
  - `**Narrative (Operator):**` the Operator's POV.
  - `**Details (<Dyad>):**` agent-supplied evidence/specifics.
  - `**Rub of the CONTINUE (agent falsifies the Operator POV):**` — apply falsification to the retro itself;
    mark each claim **survives** (with grounding) or *recorded, not rubbed* (a felt preference can't be falsified).
- **`## 2. START — what to do better`** `*(harvested from fb:/rubs)*` — bullets.
- **`## 3. STOP — what hurt (or almost did)`** `*(harvested from fb:/rubs)*` — items phrased imperatively (`**STOP <action>**`).
- **`## Forward`** — open frontier / next.

**Why:** the Rub-of-the-CONTINUE bakes our falsification discipline into the retro (the Operator's POV gets
tested, not just recorded). Interplay with [[feedback_reflection-operator-pov-continue-only]]: Operator leads
CONTINUE; Agent drafts all three + rubs the CONTINUE; START/STOP harvested realtime from fb:/rubs.
**How to apply:** every `retro:` presentation uses this structure. Distinct from harvest-to-ledger (the retro is
*how the dyad climbed*, not what it proved).
